# 复现协议

## 环境

Python 3.12.6 已在 Windows 实测。依赖：NumPy、PyYAML 和 psutil。执行 `python validate_extension.py` 检查三种进口假设、基期再现、15 题与预算；新增最终需求的需求—交付—短缺关系检查。

## 已发布实验

R1 与 G5 各为 13 情景×3 策略×10 种子×30 季度。种子 42–51，冲击乘子为 `max(0, 1 + 0.04*N(0,1))`，随机发生器种子为 `seed+15011`。该扰动是研究者设定的情景离散。G5 每期共同支出剩余预算的 0.25；总预算、渠道和起始时间一致。每次比较保持外生最终需求一致。

元数据保存配置与 SHA-256；`run_metrics.csv` 为轨迹级指标，`paired_summary.csv` 为同情景同种子的策略差异。报告均值与范围，未进行现实分布上的统计推断。OFAT 是单因素扰动，不覆盖联合参数不确定性。

最终需求履约率为全部季度最终交付之和除以最终需求之和；与逐期比例均值不同。旧积压单独分配，没有最终客户订单批次识别。内部订单及总短缺为内生指标，与最终需求短缺分别解释。

15 题演示包含 50 个对照臂×种子 1、2、3×30 季度，共 150 次。种子相同不保证所有任务启用了随机机制。性能数据为 15 题×3 种子，共 45 次；包含策略调用和逐步 RSS 采样，排除构造；RSS 为整个 Python 进程。计时取决于硬件负载。

## 2026-10-03 论文补充诊断

结算引擎及原 15 题配置保持不变。运行 `python -m scripts_ic.run_manuscript_diagnostics` 新增 426 条轨迹：R1/G5 的承接边关闭、私人资本投资关闭各覆盖三种进口分配、三策略和十种子，共 360 条；E1 两种吸收、三种进口下的基期需求诊断 6 条，以及十种子需求冲击诊断 60 条。需求冲击诊断对部门 8 在第 10–19 期增加需求，吸收条件取 0.2/0.9，AI 支出相同。

安装 `requirements_site.txt` 后运行 `python -m scripts_ic.summarize_manuscript_evidence` 汇总配对差异、15 题逐臂诊断和图表。它核对共同最终需求、匹配冲击与 E1 支出；输出保存在 `benchmark_results/manuscript_diagnostics/`。这些额外实验不构成外部验证，也未加入学习策略。`paper/SUBMISSION_EVIDENCE.md` 列出尚待完成的投稿证据。
